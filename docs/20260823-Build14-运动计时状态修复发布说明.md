# Build 14：运动计时状态恢复与同步修复

## 问题

- 用户已经点击“开始运动”，系统也在计划时长结束时发送通知。
- App 在计划结束后恢复本地记录时，旧逻辑会把进行中的运动错误转换为“已错过”。
- 运动详情页把“已错过”显示成“尚未开始”，导致用户误以为计时记录丢失。

## 修复

- 只有从未开始且超过计划结束时间的行动才自动显示为“已错过”。
- 已开始的计时跨过计划时长后继续保持“进行中”，页面显示“时间已到”，由用户选择“完成本次运动”或“继续运动”。
- 自动修复旧版本产生的异常记录：存在实际开始时间、没有结束记录的“已错过”运动恢复为进行中。
- 客户端同时间戳合并时优先保留完成度更高的状态，避免服务器旧快照覆盖本地计时。
- 后端拒绝相同时间戳下从“进行中/已完成”倒退为“未开始/已错过”的写入；显式调整使用新的更新时间，仍可正常生效。

## 验证范围

- 开始运动后进入后台，超过计划时长再返回。
- 开始运动后结束 App，超过计划时长再启动。
- 离线开始、恢复和重新联网同步。
- 已受旧版本影响的“已错过但存在开始时间”记录自动恢复。
- 真正从未开始的过期行动仍显示为已错过。
