# BPHealth 1.0（Build 3）完整发布变更日志

时间：2026-08-10（Europe/London）

基线：GitHub 提交 `0263565`（存档 GPT 功能与 Prompt 说明修订版）

目标：将基线之后完成的 iOS、Node API、PostgreSQL 迁移、测试与产品文档作为同一版本发布到 GitHub、Render 和 TestFlight。

## 1. 账号删除与研究数据保留

- Delete account 从物理删除改为去标识化停用。
- 删除后原邮箱、密码和登录令牌失效，原邮箱可重新注册为新账号。
- profile、血压、餐食、运动和 AI 用量数据继续以去标识方式保留，用于已告知用户的学术研究分析。
- 增加 `users.deleted_at`，认证中间件拒绝已停用账号，包括删除前尚未过期的 access token。
- iOS 删除账号后仍清除本机登录状态、本地读数缓存、行动数据和本地餐食照片。

数据库迁移：`20260810120000_retain_research_data_after_account_deletion`。

## 2. 餐食照片与 GPT 分析

- 餐食照片只作为 GPT 分析输入，不保存到后端数据库或对象存储。
- 分析成功后，在当前 iPhone 的 Application Support 中轻量保存压缩图；再次打开同一条记录可显示原图。
- 本地图片按用户、餐食记录和更新时间隔离，不参与 iCloud 备份，并使用文件保护。
- 修复餐食弹窗每天首次打开时右上角关闭按钮可能无响应的问题。
- GPT 餐食分析改为结构化输出：
  - AI 分析：“识别 / 饮食结构 / 烹饪方式”三段。
  - 类似建议：“饮食结构 / 烹饪方式”两段。
- Prompt 要求从支持血压管理的饮食角度生成简短、谨慎、非诊断性内容，不对照片无法确认的盐油和分量作确定判断。
- 新老客户端字段兼容；历史餐食记录继续正常展示。

数据库迁移：`20260810150000_structured_meal_analysis`。

## 3. 血压读数与趋势

- 恢复读数卡片下方的“最近血压解释”，规则负责类别与安全等级，GPT 只优化支持性表述。
- 最近 7 天趋势增加“每日取当日血压测量的平均值，呈现趋势分析”说明。
- 今日行动的早晚血压卡片内部不再重复显示时间；时间仍保留在树的中轴，早晨计划时间更新为 07:00。
- 拍照上传页删除右上角头像与姓名。
- “今天的读数”统一改为“最近的读数”；首页卡片读取跨日期的最新一条记录，不再只筛选当天数据。

## 4. 行动生成与运动时间

- 场景、当前状态、实时推荐运动和运动时间合并为单一“生成低门槛运动”模块。
- 用户每次改变场景或状态后，系统立即重新显示推荐的 4 项运动。
- “偏好运动设置”更名为“记录自定义运动”。
- 所有运动页面统一使用并排的“开始时间 / 结束时间”；血压和三餐仍是单一时间点。
- 开始时间按 30 分钟选择，结束时间按 5 分钟选择，并自动保持原运动时长。
- 个性化运动详情仅保留“标记完成”，删除“调整行动”和“跳过今天”；“保持轻松步行”改为“保持轻量运动”。

## 5. 低门槛运动文案与男女图片

- 24 条运动记录全部采用 0810 审核工作簿中的新版文案。
- 运动详情标题由“AI运动建议 / AI强度建议”改为“怎么做 / 强度建议”。
- 文案不区分男女；男性版和女性版工作簿逐条比对一致。
- 运动图片按 profile 性别切换：仅明确选择男性时使用男性版；女性、其他、不想说明或尚未选择时使用女性版。
- 新增 16 张男性版 1024px 图片，并与来源文件逐一校验。
- 自定义运动及无法映射的历史运动统一使用通用运动器械图。
- 低门槛运动选项与图片区域统一为白色背景。

## 6. iPhone 14 Pro 响应式布局与时间轴

- 修复今日行动卡片标题和时间范围被省略号截断的问题。
- 修复行动调整页“可调整 / 调整”和“为什么需要调整”文字在窄屏被挤成竖排或显示不全的问题。
- 今日行动运动卡片改为纯白底，避免透明卡片与白底运动图片不一致。
- 时间轴改为按内容高度动态布局：同一时间共用一个中轴节点，同侧多卡片自动纵向堆叠。
- 当前时间按正确顺序插入，卡片之间保持压缩但安全的间距，减少树的总长度且避免重叠。

## 7. 数据和 API 兼容性

- 运动仍使用既有 `scheduledStartAt`、`scheduledEndAt` 与 `durationMinutes`，不新增运动数据库字段。
- 新版 iOS Release 继续使用 HTTPS API：`https://bphealth-api-staging.onrender.com`。
- Render 发布必须先执行 Prisma migrations，再启动服务。
