# BPHealth 研究数据留存（Build 9）

## 目标

为约 20 名参与者、每人连续 14 天的研究保留“今日行动”在每天各时点的真实状态，便于研究结束后回看参与者设置了什么、完成了什么、调整了什么，以及最终一天的行动结果。

## iOS

- 登录用户进入“今日行动”、行动列表发生变化或 App 回到前台时，同步当天完整行动树。
- 同步内容包括行动类型、名称、说明、计划起止时间、时长、状态、完成时间、血压文字、饮食建议、低门槛运动上下文、实际运动计时等结构化字段。
- 不上传餐食、血压计或运动图片。
- 离线时不影响本地使用；下一次行动变化或回到前台时以当前完整状态补传。

## API 与数据库

- 新增 `POST /research-actions/sync`：保存当前用户当天最新完整快照。
- 新增 `GET /research-actions/days`：按日期范围读取当前用户每日快照。
- 新增 `DailyActionSnapshot`：每名用户每天一条最新快照，便于直接查看最终状态。
- 新增 `ActionEvent`：追加式记录创建、删除、状态变化、改期和内容更新，保留变化前后数据。
- 同一参与者同一天的并发同步使用 PostgreSQL 事务级 advisory lock 串行化，避免快速连续操作丢失事件。
- 删除账户仍走既有“停用/去标识化”路径，研究数据不会因物理级联删除而消失。

## 容量估算

20 名参与者 × 14 天，即使每人每天产生约 100 次变更、每次事件平均 4–8 KB，新增数据库数据通常也仅约 11–22 MB；每日最终快照约为亚 MB 到数 MB量级。该规模远低于现有 PostgreSQL 与 Node 服务所需的常规容量。

## 验证

- Node TypeScript 编译、路由单元测试与全套服务端测试。
- iPhone 14 Pro 模拟器 XCTest，包括同步请求字段与“不上传图片”断言。
- Prisma migration deploy 与真实 PostgreSQL E2E（本地 Docker 可用时）。
