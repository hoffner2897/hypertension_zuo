# Data Model

## Overview
BPHealth uses PostgreSQL on the backend and GRDB-backed SQLite storage on iOS.

Backend data is the source of truth after sync. iOS local storage supports offline reading creation, cached profile/readings, and a sync queue.

## Backend Database

### users
Represents an account.

- `id`: uuid primary key
- `email`: unique normalized email
- `password_hash`: hashed password
- `email_verified_at`: nullable timestamp
- `created_at`: timestamp
- `updated_at`: timestamp

Account deletion in the first version should hard-delete account-owned data so the same email can be used again later.

### email_verification_tokens
Stores one-time email verification tokens.

- `id`: uuid primary key
- `user_id`: foreign key to users
- `token_hash`: hashed verification token
- `expires_at`: timestamp
- `consumed_at`: nullable timestamp
- `created_at`: timestamp

Development email delivery is console-only: log the verification link or token in the server process.

### refresh_tokens
Stores long-lived refresh token records.

- `id`: uuid primary key
- `user_id`: foreign key to users
- `token_hash`: hashed refresh token
- `device_id`: client-provided stable device id
- `expires_at`: timestamp
- `revoked_at`: nullable timestamp
- `created_at`: timestamp

Access tokens are short-lived JWTs. Refresh tokens are long-lived opaque values and should be stored hashed in PostgreSQL.

### user_profiles
Stores required lightweight profile data.

- `id`: uuid primary key
- `user_id`: unique foreign key to users
- `display_name`: string
- `birth_year`: integer
- `sex`: enum
- `completed_at`: timestamp
- `created_at`: timestamp
- `updated_at`: timestamp

Sex values:
- `female`
- `male`
- `other`
- `prefer_not_to_say`

The field is for lightweight user context, not diagnosis.

### blood_pressure_readings
Represents one blood pressure reading.

- `id`: uuid primary key
- `user_id`: foreign key to users
- `client_id`: uuid generated by iOS before sync
- `systolic`: integer
- `diastolic`: integer
- `pulse`: nullable integer
- `measured_at`: timestamp
- `source`: enum
- `note`: nullable string
- `created_at`: timestamp
- `updated_at`: timestamp
- `deleted_at`: nullable timestamp

`client_id` must be unique per user. It makes offline sync idempotent and prevents duplicate uploads.

Source values:
- `manual`
- `camera_mock`
- `camera_ocr`
- `health_import`

Use `manual` and `camera_mock` first. Real OCR and HealthKit are deferred.

## iOS Local Database

Use GRDB.swift for SQLite storage.

Suggested tables:
- `local_profile_cache`
- `local_blood_pressure_readings`
- `sync_queue`
- `local_app_metadata`

Local reading sync states:
- `localOnly`
- `syncing`
- `synced`
- `syncFailed`

Token storage:
- Access token: memory only.
- Refresh token: Keychain.
- Device id: Keychain.
- SQLite: user id, profile cache, reading cache, sync metadata.

## API Contracts

First version endpoints:

```text
POST /auth/register
POST /auth/login
POST /auth/refresh
POST /auth/logout
GET  /auth/me
POST /auth/verify-email
POST /auth/resend-verification
DELETE /auth/account

GET  /profile
PUT  /profile

GET  /readings
POST /readings
PUT  /readings/:id
DELETE /readings/:id
POST /sync/readings
```

Backend errors should use stable codes, for example:

```json
{
  "code": "EMAIL_ALREADY_REGISTERED"
}
```

The iOS app maps error codes to localized Chinese and English text.

## Reading Analysis
Reading classification should stay outside SwiftUI views. The first version can use simple rule-based analysis, but the output must remain non-diagnostic.

Suggested result variants:
- `withinSelectedRange`
- `mayNeedAttention`

Use wording like "this reading", "may indicate", "recheck after a short rest", and "consider contacting a qualified health professional if readings remain elevated or symptoms are present."

## Privacy And Safety
- Treat blood pressure values as sensitive health data.
- Do not log raw passwords, tokens, or unnecessary health details.
- Store password hashes, never passwords.
- Store refresh and verification tokens hashed.
- Account deletion should revoke sessions and remove account-owned profile/readings.
