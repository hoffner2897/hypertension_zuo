# BPHealth 账户删除与餐食记录修复日志

时间：2026-08-10 14:55（Europe/London）

状态：本地实现及测试完成；尚未提交、推送或部署到 Render / TestFlight。

## 本轮需求

1. 用户执行 Delete account 后，学术研究需要的后端数据不再随账号级联删除。
2. 餐食照片仍不上传后端，但同一台 iPhone 再次打开已记录餐食时应能显示原照片。
3. 修复每天第一次打开餐食记录弹窗时右上角关闭按钮无响应的问题。

## 1. 账号删除改为去标识化停用

### 修改前

- `DELETE /auth/account` 直接执行 `prisma.user.delete`。
- profile、血压读数、餐食记录、运动记录及 AI 用量表都通过外键 `ON DELETE CASCADE` 被删除。
- 因此旧实现不满足研究数据保留要求。

### 修改后

- `users` 增加 `deleted_at`，删除账号时设置为当前时间。
- 原邮箱替换为不可用于联系的内部墓碑邮箱；原邮箱可重新注册为全新账号。
- 密码哈希替换为随机密码的哈希，原凭证永久失效。
- profile 的显示名称替换为研究参与者编号；出生年、性别及健康上下文保留为去标识研究数据。
- 所有 refresh token 当场撤销，未使用的邮箱验证 token 标记为已使用。
- 认证中间件只接受 `deleted_at IS NULL` 的用户，因此删除前签发、尚未过期的 access token 也会立即失效。
- 血压、餐食、运动、AI 用量及去标识 profile 行不删除，继续通过原有 UUID `user_id` 关联。
- iOS 端仍清除本机登录状态、本地血压缓存、行动历史及本地餐食照片。

### 数据库迁移

- `server/prisma/migrations/20260810120000_retain_research_data_after_account_deletion/migration.sql`
- Render 部署前必须执行 `npm run db:deploy`；没有先应用迁移的旧后端不能运行本次代码。

## 2. 餐食照片本地轻量保存

### 存储边界

- 后端 `/meal-records/analyze` 仍只保存 `analysis`、`similarSuggestion`、`cardSummary` 等文字结果，不保存照片或照片 URL。
- iOS 复用上传给 API 的压缩 JPEG，在分析成功后写入本机 Application Support。
- 文件设置为不参与 iCloud / 设备备份，并使用完整文件保护。
- 缓存按 `userId + mealRecordId + updatedAt` 隔离，避免换账号或后端记录已更新时展示不匹配的旧照片。
- 同一餐食重新分析后，新版本照片替换旧版本文件。
- 删除账号时只清除该用户的本机餐食照片，不影响其他登录用户的本地缓存。
- 换手机、卸载 App、手动清理本机文件或记录版本不匹配时，界面继续显示“餐食图片未保存”占位状态。

## 3. 首次打开弹窗关闭按钮

### 原因与处理

- 旧按钮只调用子视图的 SwiftUI `dismiss()`；首次由 `.sheet(item:)` 建立的状态链路中出现了无法可靠关闭的反馈。
- 新实现给餐食弹窗传入明确的 `onClose`，点击右上角关闭按钮会直接把父页面的 `activeMealItem` 设为 `nil`。
- 关闭按钮维持 44 × 44 点击区域，并补充稳定的 UI 测试标识。
